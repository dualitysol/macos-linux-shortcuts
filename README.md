# Горячие клавиши macOS без установки программ

Это экспериментальный скрипт настройки встроенных функций macOS, а не оконный менеджер.
На Mac его ещё не проверяли: здесь доступна только Linux-среда. Проверка синтаксиса
и логики не подтверждает, что конкретная версия macOS применит все настройки.

Требования: macOS 15 или новее, английское меню окон, установленный iTerm2.
Ничего скачивать, устанавливать через Homebrew, компилировать или запускать через sudo не нужно.
Скрипт использует штатные Bash, osascript/JXA и системные фреймворки Apple.

## Что настраивается

Здесь Super означает логическую Command, Ctrl — логическую Control.

| Сочетание | Действие |
|---|---|
| Ctrl+Super+← / → | Предыдущий / следующий рабочий стол |
| Super+← / → | Левая / правая половина рабочей области |
| Super+↑ | Заполнить рабочую область; это не отдельный полноэкранный Space |
| Super+↓ | Вернуть размер окна до размещения плиткой |
| Ctrl+Shift+C / V в iTerm2 | Copy / Paste через штатные команды iTerm2 |
| Ctrl+C в iTerm2 | Отправить 0x03 (обычное прерывание команды) |
| Ctrl+V в iTerm2 | Отправить 0x16 (обычная функция Control+V терминала) |
| Ctrl+← / → в iTerm2 | Прыжок по словам (Esc+b / Esc+f для readline/zsh) |
| Ctrl+Shift+← / → в iTerm2 | Без изменений: переместить вкладку влево/вправо |

**Ctrl+←/→ в iTerm2 заменяет штатное переключение сессий/панелей (Select Previous/Next Session)
на этих же клавишах.** Если вы используете это переключение, привяжите его в iTerm2 к другому
сочетанию перед применением. Shift-вариант (перемещение вкладки) не затронут.

Автоматическая перестановка рабочих столов по частоте использования отключается.
Новые столы скрипт не создаёт: добавь нужное число через Mission Control.
Оконные сочетания работают в приложениях с соответствующими пунктами Window → Move & Resize.
В приложении без этих пунктов, с собственными конфликтующими сочетаниями или в полноэкранном
режиме поведение может отличаться. Command+стрелки будут заняты оконными командами
там, где приложение их принимает, вместо привычной навигации по тексту.

**Super+Shift+1…9 для переноса окна не реализованы.** В настройках macOS нет такой
штатной команды. Переключение на стол и перенос окна на него — разные операции.
UI-макрос через Mission Control или удержание заголовка окна потребует разрешений
Accessibility/Automation и проверки на целевом Mac. Скрипт не выдаёт эти разрешения
и не меняет ограничения организации. Предсказуемый перенос одним сочетанием
в рамках только этих настроек обещать нельзя.

## Запуск

Сохрани `setup.command` на Mac. Открой встроенный Terminal и перейди в папку с файлом.
**Для твоей уже настроенной Fn → Command рекомендован режим `--fn-command`.**
Он сохраняет переназначение Fn и использует физическую Control в роли Linux Super.
Физические сочетания будут такими:

| Физические клавиши | Действие |
|---|---|
| Fn+Control+← / → | Сменить рабочий стол |
| Control+← / → | Окно на левую / правую половину |
| Control+↑ / ↓ | Заполнить рабочую область / вернуть размер |
| Fn+Shift+C / V в iTerm2 | Копировать / вставить |
| Fn+C в iTerm2 | Прервать команду |
| Fn+← / → в iTerm2 | Прыжок по словам (заменяет переключение сессий/панелей) |
| Fn+Shift+← / → в iTerm2 | Без изменений: переместить вкладку влево/вправо |
| Fn+← / → в Cocoa-приложениях (TextEdit, Mail, Xcode…) | Прыжок по словам, см. ниже |
| Fn+C / V в остальных приложениях | Прежние Command+C / V |

Этот режим предполагает, что Fn уже выдаёт Command, а физическая Control — Control.
Он не проверяет и не меняет физическое переназначение. Для освобождения Control+↑/↓
он отключает стандартные сочетания Mission Control / App Exposé, если они не были изменены.
В iTerm2 настоящие клавиши Command тоже будут давать новые сочетания копирования,
поскольку приложение получает одинаковый сигнал от них и от переназначенной Fn.

Предварительный просмотр:

```sh
bash setup.command --fn-command
```

Сохрани нужные сессии, закрой iTerm2 и System Settings. Применение из Apple Terminal:

```sh
bash setup.command --apply --fn-command
```

Выйди из учётной записи и войди снова. Это основной вариант для твоего текущего случая.

## Альтернативная схема с настоящей Control на Fn

Предварительный просмотр ничего не меняет и работает даже при открытом iTerm2:

```sh
bash setup.command
```

Если нужна предложенная физическая раскладка, сначала посмотри её план:

```sh
bash setup.command --linux-modifiers
```

Для применения заверши iTerm2 обычным способом, сохранив нужные сессии, и закрой
System Settings, чтобы открытые окна настроек не перезаписали изменения.
Выполни в Apple Terminal:

```sh
bash setup.command --apply --linux-modifiers
```

Затем выйди из учётной записи macOS и войди снова. Скрипт сам этого не делает.
Схема с `--linux-modifiers`:

| Надпись на физической клавише | Сигнал для macOS | Роль в выбранной Linux-схеме |
|---|---|---|
| Fn / 🌐, крайняя слева | Control | Ctrl |
| Левая Control | Command | Super |
| Option | Без изменения | Alt, если ранее не переназначалась |
| Command у пробела | Без изменения | Дополнительная Command, если ранее не переназначалась |

Например, переход между столами — физические Fn+Control+стрелка,
копирование в iTerm2 — Fn+Shift+C, прерывание — Fn+C.
**В остальных приложениях Fn+C после этой схемы не станет обычным Copy:**
для стандартных macOS-команд остаётся Command+C (в том числе физическая Control+C).
Это компромисс данной схемы, а не полная эмуляция Linux-клавиатуры.

Чтобы сохранить нынешнее расположение модификаторов, используй:

```sh
bash setup.command --apply
```

Тогда сочетания из первой таблицы обозначают логические клавиши после твоих
существующих переназначений. Если Fn сейчас выдаёт Command, она действует как Super,
а Ctrl+Shift+C нажимается через ту клавишу, которая действительно выдаёт Control.

Автоматическое переназначение ищет уже существующую настройку Fn для единственной
клавиатуры. Если однозначно найти её не удаётся, скрипт останавливается до записи.
Тогда те же назначения можно сделать в System Settings → Keyboard → Keyboard Shortcuts → Modifier Keys.
Без назначения другой клавиши на Fn комбинации, которым нужна настоящая Fn, через неё недоступны.

## Прыжок по словам вне iTerm2

`setup.command` сам пишет файл `~/Library/KeyBindings/DefaultKeyBinding.dict` (резервная копия
и откат — как для остальных настроек, через `--undo`). Он переопределяет `moveWordLeft:`/
`moveWordRight:` (Shift-варианты — выделение) во всех Cocoa-приложениях: TextEdit, Mail, Xcode,
**Outlook** (классический, не "New Outlook" — см. ниже) и т.п.

- Control+←/→ прописывается всегда, независимо от флагов. Обычный Control+стрелка по умолчанию
  переключает рабочие столы (Mission Control), а этот скрипт уже переносит данное сочетание на
  Control+Command+стрелку (см. выше), так что голый Control+стрелка свободен в любом режиме.
- Command+←/→ (физически Fn+←/→) добавляется только с `--fn-command`, где настоящая Command не
  нужна под Super и иначе означала бы переход в начало/конец строки.

Файл не ставится, не требует логаута — подхватывается после перезапуска конкретного приложения.
**Не работает в приложениях не на Cocoa**: Slack, VS Code, Telegram Desktop, Firefox, Chrome
(кроме адресной строки — см. ниже) используют свою текстовую систему, а не Cocoa NSResponder.

Обычный Terminal.app (не iTerm2) этим файлом не покрывается и не настраивается `setup.command` —
у него нет документированного формата для программной записи кастомных сочетаний. Добавь вручную:
Terminal → Settings → Profiles → [профиль] → Keyboard → "+" → Command+← → action "send text",
значение `\033b`; затем Command+→ → "send text", значение `\033f`. Это тот же код Esc+b/Esc+f,
который readline/zsh уже понимают как «слово назад/вперёд».

## VS Code

`setup.command` также пишет `~/Library/Application Support/Code/User/keybindings.json`, если
VS Code установлен (проверяется по bundle id, иначе шаг пропускается). Добавляются четыре
привязки — `ctrl+left`/`ctrl+right` → `cursorWordLeft`/`cursorWordRight`, `ctrl+shift+left`/
`ctrl+shift+right` → выделение словом, только при фокусе в текстовом поле (`textInputFocus`,
встроенный терминал не затронут). Существующие сочетания в файле сохраняются; меняются только
эти четыре ключа. Если файл содержит `//`-комментарии или не парсится как JSON, скрипт
останавливается до записи и просит добавить привязки вручную.

## Другие приложения

- **Microsoft Teams, Telegram Desktop, Firefox** — у них уже работает прыжок по словам на
  Ctrl+←/→ "из коробки" (встроенная обработка в самом приложении), ничего настраивать не
  пришлось и `setup.command` их не трогает.
- **Chrome** — адресная строка — нативный Cocoa-контрол, покрывается тем же
  `DefaultKeyBinding.dict`, что и остальные Cocoa-приложения. Текст на самих страницах
  (формы, textarea, Gmail и т.п.) рендерится движком Blink и не настраивается ни файлом, ни
  флагом — у Chrome нет публичного способа переопределить это сочетание без установки
  системного перехватчика нажатий (например, Karabiner-Elements), что выходит за рамки этого
  скрипта.
- **"New Outlook"** (переключатель в правом верхнем углу приложения) — веб-движок, а не Cocoa;
  `DefaultKeyBinding.dict` его не затронет. Переключись на классический Outlook или смотри
  вариант с Chrome выше.

## Проверка и откат

Проверь сначала Finder или TextEdit: в меню Window → Move & Resize должны появиться
новые сочетания. Проверь обе стрелки между двумя рабочими столами. В iTerm2 выдели
обычный текст, скопируй Ctrl+Shift+C, вставь Ctrl+Shift+V, затем запусти `sleep 30`
и прерви Ctrl+C. В режиме `--fn-command` для этой проверки нажимай физическую Fn
вместо Ctrl. Отдельно проверь привычные латинскую и кириллическую раскладки.

Скрипт меняет общие и сохранённые профильные привязки iTerm2, сохраняя прочие записи.
Динамические профили и собственное переназначение модификаторов внутри iTerm2
могут потребовать отдельной настройки. Загрузка настроек iTerm2 из общей папки
не поддерживается: скрипт остановится до записи. Названия Copy/Paste предполагаются английскими.

Для отката снова закрой iTerm2 и System Settings, выполни в Apple Terminal:

```sh
bash setup.command --undo
```

И выйди/войди в учётную запись. Резервная копия хранится локально:
`~/Library/Application Support/LocalLinuxShortcuts/backup.json`.
Она может содержать настройки профилей iTerm2; не публикуй её целиком.
Откат возвращает только затронутые ключи предпочтений. Если какой-либо ключ
изменился после запуска, откат пропускает его и оставляет резервную копию,
чтобы не затереть более новые настройки. Установка не запускает фоновых служб.
